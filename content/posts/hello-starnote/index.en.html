In one sentence: you write in StarNote, the website lives in your own GitHub repository. StarNote only commits post files (front matter + body HTML); GitHub Actions builds the whole site with this template. The repository is yours and keeps working without StarNote.

Three steps

  1. Click Use this template; name the repository <username>.github.io.

  2. Create a fine-grained token for that repository only (Contents and Pages: read and write).

  3. Paste the repository and the token into StarNote → Connect GitHub. StarNote turns Pages on and publishes your first post.

With any other repository name the site lives under /repository-name/; the template handles every link for you.

What happens on publish

StarNote writes the post folder in a single commit through the GitHub API:

content/posts/hello-starnote/
├── index.zh.html   # Chinese original
├── index.en.html   # English translation (optional)
└── cover.png       # cover and body images
1234
Bash

The push runs .github/workflows/pages.yml: install, npm run build, upload _site/, deploy.

Two languages

Chinese lives at the root, English under /en/. Both versions of a post sit in one folder and point at each other with hreflang; a post written in one language shows no language switch.

Your site, your content: post files are plain front matter + HTML that Jekyll, Hugo or Eleventy can read as is.
